# Архитектура

## Общая картина

```
Браузер / телефон (PWA)
 ├─ Интерфейс (React): разделы в src/modules/
 ├─ Настройки разделов, роли, план: src/config.ts
 ├─ Демо-данные: src/seed.ts
 └─ Слой хранения: src/store.tsx  →  сейчас localStorage, потом облако
```

Всё работает на устройстве. Сервера нет, поэтому нет и расходов на хостинг: сайт отдаёт GitHub Pages.

## Ключевые решения

**PWA вместо нативных приложений.** Один код работает как сайт и как приложение на Android и iPhone. Установка через «На экран Домой», без App Store и Google Play. Если позже понадобятся push-уведомления или публикация в магазинах, готовую PWA можно обернуть через Capacitor, не переписывая интерфейс.

**Данные за «адаптером».** В `src/store.tsx` описан интерфейс `StorageAdapter` из двух методов: `load` и `save`. Сейчас реализован `localAdapter`. Для облака нужно написать второй адаптер (например, на Supabase) и подставить его одной строкой. Интерфейс разделов при этом не меняется.

**Разделы как модули.** Каждый раздел — отдельный файл в `src/modules/`. Реестр лежит в `src/config.ts`. Добавление раздела: запись в реестре, новый файл, строка в `App.tsx`. Включение и выключение разделов пользователем уже работает.

**Настройка без кода.** Названия точек, нормы эспрессо, валюта, видимость разделов меняются в интерфейсе. Содержимое «Пути шефа», навыков и должностей меняется в `src/config.ts`; в roadmap это переезжает в интерфейс.

**Копия на Google Диск.** `src/backup.ts` собирает данные в готовые листы (шапка, строки, подсветка) и отправляет их POST-запросом веб-приложению Google Apps Script, которое пользователь разворачивает у себя (код скрипта лежит в том же файле, константа `APPS_SCRIPT`). Скрипт ничего не считает, только записывает листы и JSON, поэтому при изменении панели меняется только `buildSheets`, а скрипт обновлять не нужно. Вход в Google через сайт не используется: браузер не даёт открывать окно входа без нажатия, а автосохранение должно работать само. Адрес скрипта хранится отдельно от данных панели (ключ `chief-hub-backup` в localStorage) и в выгрузку не попадает.

**Оффлайн.** Сервис-воркер `public/sw.js` кэширует оболочку, приложение открывается без сети.

## Структура репозитория

```
.github/workflows/deploy.yml   автопубликация на GitHub Pages
public/                        иконка, манифест PWA, сервис-воркер
src/
  App.tsx                      каркас: меню, выбор точки
  backup.ts                    копия на Google Диск: листы таблицы, отправка, код скрипта
  config.ts                    реестр разделов, навыки, план шефа
  seed.ts                      демо-данные
  store.tsx                    хранилище и расчётные функции
  types.ts                     описание данных
  modules/                     Обзор, Качество, Команда, Склад, Показатели, Оборудование, Обходы, Отчёт, Путь шефа, Настройки
docs/                          продукт, архитектура, roadmap, должностная инструкция
```

## Облако: как будет устроено

Рекомендуемый вариант: Supabase (PostgreSQL + вход по почте + права доступа на уровне строк).

- Таблицы повторяют модель данных из `types.ts`.
- Роли: владелец сети, шеф, управляющий точки, бариста. Бариста видит и вводит данные только своей точки.
- Синхронизация: запись сначала в локальное хранилище (работает без сети), затем отправка на сервер.

## Правила для разработчика

- Расчёты (нормы, дефицит, средние) живут в `store.tsx`, не внутри разметки.
- Новые поля данных добавляются в `types.ts` и `seed.ts`. При смене формы данных поднимать `version` и дописывать миграцию `migrate()` в `store.tsx`: она приводит сохранённые данные и загруженные файлы к текущей версии (сейчас 4; версия 1 получает пустые новые списки и нормы по умолчанию, версия 3 переводит склад в базовые единицы г, мл, шт и собирает банк ингредиентов из стандартов).
- Сигналы «что требует внимания» и недельный отчёт считаются в `buildSignals` и `buildReport` в `store.tsx`. Новый сигнал добавляется там, и он сам попадёт в Обзор и Отчёт.
- Порядок разделов в `MODULES` повторяет должностную инструкцию (`docs/JOB_DESCRIPTION.md`).
- Цвета и размеры берутся из переменных в `styles.css`; тёмная тема уже поддержана.
